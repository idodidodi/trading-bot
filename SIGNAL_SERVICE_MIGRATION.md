3. With an explicit administrator export connection, run `scripts/export-execution.py --writers-stopped --output /absolute/protected/snapshot.json` and `EXECUTION_EXPORT_DATABASE_URL` set privately. Import requires an empty journal, is atomic and idempotent for the same snapshot, preserves broker IDs/source IDs/embedded signal evidence, records counts/digest, and forces execution disabled. No broker calls occur. 5. Revoke/rotate the old broker-capable credentials and remove them from the signal installation. A file lock prevents concurrent owners of one executor journal, but cannot fence a copied journal or another host: credential rotation and stopping the old owner are mandatory operational fences.

## Recovery and limits

Pause entries before changing state; stopping the executor also pauses automated management, so reconcile broker protection first. Never start the old execution owner alongside the new one. After any new orders, use forward repair or reconcile and migrate the current journal back under a separately reviewed procedure; a source rollback cannot undo broker effects. Restore Telegram only from its own preserved journal and offsets.

The new execution-notice handoff adds an HTTP dependency. Notices are durably retried with the original ID/time and enter the unchanged Telegram queue; an API outage can delay them. No claim of identical wall-clock latency or exactly-once Telegram delivery is made. Legacy broker-adapter limitations remain; no live adapter certification was performed. SQLite is a single-owner execution journal, not a multi-host HA database. Historical simulation requires recorded candles; the executor does not gain access to signal-service candle tables.
