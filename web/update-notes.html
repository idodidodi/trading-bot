Scanner changelog & FMP setup

Source update · October 18, 2026 · Pending executable release

Telegram readability

Telegram messages now use bold headings and market/signal details, italic timestamps and footnotes, and clearer spacing. Wording, prices, units, timestamps and source labels are preserved.

Paper trading setting

The local production Settings menu now includes an Alpaca paper trading toggle, saved on the scanner computer and applied without restarting. Development paper trading remains disabled. Turning automation off preserves existing simulated orders and positions at Alpaca; an in-progress cycle may finish.

Local development settings

In the local development dashboard, Settings & versions now includes Telegram delivery and cloud sync overrides. Choices are saved on the scanner computer and apply without restarting. Use while production is stopped. Credentials remain in the local environment file.

What changed

Fixed forex weekend alerts. All forex candle timeframes pause from Friday 17:00 until Sunday 17:00 New York time, including catch-up scans and daylight-saving changes. Provider candles wholly inside the weekend closure are excluded before caching and signal detection, including after reopening.

Linux verbose activity and error logs now persist across terminal-launched updates and detached restarts in logs/runtime.log under the application directory. Logs rotate at 5 MiB with three backups. Download verification, executable replacement and the restarted app's startup are recorded even if the original terminal is closed.

Fixed SQLite write contention that could stop scanner and paper-trading workers with “database is locked.” Cloud sync now queues small batches without holding the writer while reading and serializing all saved history. Scanner workers retry temporary locks, and activity logging can fall back to the launch terminal. Disabled paper trading stops its background polling loop.

Scanner and local UI updates on the main branch publish a new executable version automatically after both platform builds pass. The Linux process checks daily at 05:00 Israel time, downloads a newer verified executable and restarts without needing a browser page open. Keep the app running; a missed deadline is checked once on resume. Windows keeps startup and hourly checks. Check for app update requests an immediate background check. Installed apps compare release version numbers; source commit fingerprints are shown separately in Settings.

Update your local credentials

Stop the scanner and edit its existing credentials file using a local text editor. Keep all other settings.

  • Source checkout: .env beside platform_app.py.
  • Linux app: ~/.config/FamilyTradingBot/.env; an absolute XDG_CONFIG_HOME changes the config directory.
  • Windows app: %LOCALAPPDATA%\FamilyTradingBot\.env.
  • If your installation selects a custom TRADING_BOT_ENV_FILE, edit that file.

Add or update this line, replacing the placeholder with your own key only in that local file:

FMP_API_KEY=YOUR_OWN_FMP_API_KEY

On macOS/Linux, restrict the actual file to your user:

chmod 600 /absolute/path/to/.env

On Windows, keep the file in your private user profile. If the folder is shared, restrict file access in Properties → Security.

Restart the scanner. A process environment variable with the same name overrides the file; update it as well if you set one.

Enable an existing SPX asset

In Assets choose FMP cash indices, symbol ^GSPC, exchange INDEX, market index. Choose daily, weekly and monthly only, confirm the feed, and enable SPX. A new feed starts with a signal baseline.

Source installations can verify and activate the feed, back up SQLite and export history using:

.venv/bin/python scripts/activate-fmp.py --database /absolute/path/to/signals.sqlite3

Use the database for your installation. Fresh installations include the SPX default; upgrades preserve saved asset settings. Online asset editing needs the updated cloud/providers.sql migration.

Keep the key private

Enter the real key only in the local credentials file or process environment. Do not enter it in Assets or the online dashboard, or include it in screenshots, chat, Git or release notes. The example file contains an empty key. Executable updates preserve your existing credentials and bundle only the empty template. FMP errors shown by the scanner exclude authenticated URLs and provider response bodies.

This page never reads or submits credentials. If a key is exposed, replace it in your FMP account and update the local file.
