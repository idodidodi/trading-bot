# Daily momentum continuation

Momentum is independent of the existing RSI divergence strategy. Signals and Backtests each have a strategy dropdown that defaults to RSI divergence. Momentum uses only completed daily candles. It creates at most one new US stock and one new crypto candidate per daily scan; a market without a qualifying setup has an explicit result, never a forced trade.

The stock screen uses the checked-in S&P 400 and S&P 500 universe through Alpaca, respecting disabled configured tickers. Crypto uses enabled configured and daily-selected exact pairs through their daily provider. Historical universe membership, venue liquidity, short availability, earnings, funding and borrow costs are not modeled. Sell means a short candidate, not an instruction to sell an existing holding. There is no order execution.

A buy requires yesterday's close above the highest high of the preceding 20 candles, today's close still above that range, and a green confirmation candle. EMA20 must exceed EMA50; EMA50 must rise over five candles. Ten-candle return must reach 2%, and directional efficiency (net movement divided by total absolute close-to-close movement) must reach 0.35. The close must be between EMA20 and two ATR14 above EMA20. Sell conditions are symmetric. ATR uses Wilder smoothing; EMA starts at the first available close, with 80 closed candles required before selection.

Rank qualifying candidates by absolute ten-candle return divided by ATR percent, multiplied by efficiency, with symbol tie-breaks. The reference entry is the confirmation close. The permitted next-session opening price is within 0.5 ATR of that close. Stop is 1.5 ATR away and target is 3 ATR away. Skip an opening gap outside that range or a resulting reward/risk below 1.5. Exit at stop, target, or the tenth session's close. These parameters are an initial research hypothesis, not an established profitable edge. The model costs 10 basis points per side.

The live simulation never enters before publication: it uses the first later native daily session open. At 08:00 Israel time, crypto's immediately following midnight open has already passed, so the live simulation waits for the next midnight open. Stock entries wait for the next US session. Live scanning cannot reconstruct an intraday fill from daily OHLC. Backtests assume entry immediately after the confirmation at the next native session open and disclose that latency difference. If both stop and target are touched on a candle, count the stop first. Adverse opening gaps execute at the opening price. The simulator counts separate trade returns, not a portfolio with cash constraints.

The scanner catches up on startup and wakes at **08:00 Asia/Jerusalem** daily; partial coverage retries hourly. Stocks check the latest completed US session with the existing holiday calendar. Crypto must have a close within the last 36 hours. Restarts preserve daily selections and published picks. Retries can fill a missing market, but cannot replace an issued pick. Weekend/holiday scans do not republish the same stock confirmation. Rotating crypto feeds remain monitored for recent published outcomes.

`python3 momentum.py --scan` runs a bounded daily scan and prints the views. Without `--scan`, it reads persisted results only. `python3 momentum_review.py` records a review in SQLite and `data/momentum-reviews/`. Use the configured `.venv/bin/python` on this installation. The main worker performs scans automatically. Keep the worker/computer online. Codex heartbeat automations verify daily scans and review strategy results every three days.

Daily backtests replay each historical close and rank only candidates known at that close. They use each source's available recent history and current universe; this introduces selection and survivorship bias. The UI shows the latest 100 candidates and aggregate metrics for the replay. Forward outcomes, replay results, costs, entry gaps and coverage must be considered separately. Wait for at least 30 completed forward trades per market, validate any proposed change on untouched later history, and version accepted rule changes. Keep a rule snapshot on every issued signal.

Technical indicators are general building blocks, not evidence validating this strategy; see [Fidelity's indicator guide](https://www.fidelity.com/learning-center/trading-investing/technical-analysis). Thresholds and execution rules above are project design choices.

Hosted deployment: apply `cloud/momentum.sql` **after all installed migrations**, restart the local scanner/sync worker and publish `node cloud/build.mjs` through the existing Cloudflare deployment. The migration preserves the installed family authorization dispatcher and reads dedicated bounded `summary` records. It neither changes RSI evidence nor adds browser write access to momentum records. Do not apply older dispatcher migrations afterward without reapplying this wrapper.
